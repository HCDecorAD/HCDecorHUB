# HC AutoChat V1 — Public Entry Command/API

Public Entry lets another Chat/HCDR caller create one new ChatGPT conversation and deliver exactly one initial prompt.

## Command

```bat
scripts\autochat.cmd new --title "HC Future – Scholarship Companion" --prompt "Continue the project from its latest checkpoint."
```

Equivalent Python entry:

```bat
python scripts\autochat.py new --title "<title>" --prompt "<prompt>"
```

## Success JSON

```json
{
  "ok": true,
  "title": "<requested title metadata>",
  "conversation_id": "<canonical conversation id>",
  "url": "https://chatgpt.com/c/<canonical conversation id>",
  "last_user_text": "<exact prompt>",
  "target_id": "<current CDP target id>"
}
```

Callers MUST use `conversation_id` / `url` as identity. `target_id` is runtime-only and may change after browser restart.

## HCDR flow

1. Invoke Public Entry on HOCUONG.
2. HC AutoChat creates a fresh ChatGPT target through CDP.
3. It waits for the fresh composer and confirms the page is not an existing conversation.
4. It inserts the prompt and reads the composer back exactly.
5. It submits through the composer-scoped Send control.
6. It waits until ChatGPT assigns a canonical non-local conversation ID.
7. It verifies the same conversation ID, user-message count increment, and exact landed prompt.
8. Only then does it return success JSON to HCDR/caller.

The command is fail-closed. A missing composer, identity mismatch, non-canonical temporary ID, or exact-send mismatch returns non-zero/error instead of reporting success.

## Title behavior

`--title` is caller metadata in V1 Public Entry. The returned ChatGPT conversation title may initially be generated by ChatGPT from the prompt. Conversation identity is always the canonical ID/URL, never the visible title.

## Requirements

Managed Edge/CDP must be running with the HC AutoChat profile. Keep the existing exact-send, one-target-only and STOP ALL policies. Never broadcast this entry command.
